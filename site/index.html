Three steps, and only two of them are yours

  1. 01

    Type the complaint

    Sam from support writes in plain English, with no @-mention. Triage is the room's main agent, so every message reaches it.

  2. 02

    Watch the crew hand off

    Repro, CI, Fixer and Reviewer pass the ticket along in one thread, each addressed by its Switch room role.

  3. 03

    Press Approve

    The engineering lead gets a Switch approval card. One click merges; triage tells support what to say to the customer.

Triage files a ticket a developer could act on

Claude Code reads the code, finds the line responsible, and writes up the expected and actual numbers. Duplicates never get this far: triage checks the room's known-issues document first and replies with the workaround.

No fix without a failing test, and the test is locked

Codex writes the reproduction. CI, which is plain code with no model, watches it fail and records the commit. If the fixer edits that test later, CI rejects the fix.

A different model reviews, and a person approves

Code written by Claude Code is reviewed by Codex. In one run Codex sent a CSV fix back for turning empty cells into the text "null". Then CI raises a native Switch approval card that only the lead's answer can close.

Support hears how it ended

Triage explains the bug to Sam in plain words and drafts a reply he can paste to the customer. Every merge goes into the fix-ledger room document, with the time it took and who approved it.

Switch is the whole wiring

Every hand-off is a Switch message addressed to a room role. No agent keeps ticket state in memory; each one rebuilds the ticket by reading its thread. The room carries the roles, the instructions, both documents, the approval cards and the rule that only the lead may approve.

  • Roles triage, repro, fixer, reviewer and ci, each held by one agent
  • Main agent so support never types an @-mention
  • Room documents known-issues for dedup, fix-ledger for the audit trail
  • Approval cards plus an owner-only addressing policy on @ci
  • Agent protocol all five agents are WebSocket + HTTP clients

Questions

Do I need Slack or a company workspace?

No. The stack includes Mattermost, so everything runs on your laptop. Switch also bridges Slack, Teams, Discord and Telegram; Fixline was tested on Mattermost.

Which agents does it use?

The Claude Code and Codex CLIs you already have, run headless inside a separate git worktree for each ticket. The CI gate is ordinary code.

Where does my code go?

To Anthropic and OpenAI through their own CLIs, exactly as when you use them in a terminal. Switch, Mattermost and git all run locally in Docker and on your disk.

What if a fix is wrong?

It has to pass the locked repro test and the whole suite, then a second model's review. After that the lead can press Decline, and the branch is parked instead of merged.

How long does setup take?

One make up (the first run pulls images), one make setup (about 30 seconds), then make crew. You need Docker, Node 20+ and both CLIs signed in.
